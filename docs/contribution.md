# 贡献说明

感谢你愿意参与整理智能车竞赛资料。这个项目的长期价值来自持续、准确、可追溯的维护。

## 可以贡献什么

- 新增 GitHub、Gitee 或其他开源仓库链接。
- 新增 B 站公开视频、比赛录像、调车演示、经验分享。
- 补充年份页面中的规则变化、赛题信息和资料索引。
- 补充组别页面中的技术路线、常见问题和优秀资料。
- 编写知识库文章，例如控制算法、视觉处理、传感器、嵌入式工程、调参流程。
- 修复失效链接、错误归类、错别字和过期描述。

## 资料条目建议格式

```markdown
### 资源标题

- 链接：
- 类型：GitHub / B 站 / 博客 / 论文 / 工具 / 课件 / 其他
- 年份：2024 / 2023 / 多年份 / 未知
- 组别：摄像头组 / 电磁组 / 平衡组 / AI 视觉组 / 通用 / 未知
- 关键词：
- 简介：
- 推荐理由：
- 授权说明：
- 维护状态：活跃 / 停更 / 未知
```

## 分类建议

优先按以下顺序归类：

1. 如果资料明确对应某一年比赛，放到 `docs/years/` 对应页面。
2. 如果资料明确对应某个组别，放到 `docs/groups/` 对应页面。
3. 如果资料是通用方法或教程，放到 `docs/knowledge/`。
4. 如果资料横跨多个组别或年份，可在多个入口页互相链接，但正文只保留一份。

## 质量标准

新增资料前，请尽量确认：

- 链接可以打开。
- 标题、作者或来源清晰。
- 年份和组别判断有依据。
- 内容不是明显搬运、广告或低质量重复内容。
- 如果是代码仓库，最好包含 README、许可证或基本构建说明。
- 如果是视频，最好补充视频主题、适合阶段和关键看点。

## Markdown 写作约定

- 使用中文简体。
- 标题层级从 `#` 开始，不跳级。
- 链接文字尽量描述内容，不使用“点这里”。
- 列表项保持短句，必要时再补充说明。
- 对无法确认的信息标注“待确认”，不要猜测成事实。
- 不直接搬运大段原文，优先写摘要并链接来源。

## 推荐提交流程

1. 新建分支。
2. 按目录补充或修改 Markdown 文件。
3. 本地检查链接、标题层级和表格格式。
4. 提交 Pull Request，并说明新增资料类型、年份、组别和来源。

## 维护者审核重点

- 是否符合收录范围。
- 是否放在合适目录。
- 是否有足够元信息支持搜索和筛选。
- 是否存在版权、隐私或不当传播风险。
- 是否与已有资料重复。
