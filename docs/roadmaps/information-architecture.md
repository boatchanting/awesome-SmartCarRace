# 信息架构路线图

本文描述站点内容结构和未来扩展方式，作为后续开发 GitHub Pages 网站、搜索和筛选功能的基础。

## 核心导航

建议主导航保持简洁：

- 首页：项目定位、快速入口、贡献方式。
- 年份：按竞赛年份浏览资料。
- 组别：按竞赛组别浏览资料。
- 知识库：按技术主题浏览文章。
- 路线图：站点规划和维护规范。

## 内容模型

### 资源 Resource

资源是最小可索引单元，可以是仓库、视频、文章、课件、论文或工具。

建议字段：

| 字段 | 说明 |
| --- | --- |
| title | 资源标题 |
| url | 原始链接 |
| type | GitHub、B 站、博客、论文、工具等 |
| years | 关联年份，可多个 |
| groups | 关联组别，可多个 |
| tags | 关键词 |
| summary | 简介 |
| reason | 推荐理由 |
| license | 授权或版权信息 |
| status | 活跃、停更、失效、待确认 |

### 年份 Year

年份页用于承载特定赛季的规则、赛题、变化和代表性资料。

建议结构：

- 年份概览
- 规则与赛题
- 组别变化
- 代表性开源项目
- 公开视频
- 复盘文章
- 待补充清单

### 组别 Group

组别页用于承载某类比赛任务的技术路线和资料入口。

建议结构：

- 组别简介
- 常见硬件
- 常见软件架构
- 关键难点
- 开源项目
- 视频资料
- 知识库关联

### 知识文章 Knowledge

知识文章承载跨年份、跨组别可复用的内容。

建议结构：

- 背景与适用场景
- 基本概念
- 常见实现
- 调试方法
- 推荐资料
- 延伸阅读

## URL 规划

建议保持短路径：

```text
/years/2024
/years/2023
/groups/camera
/groups/electromagnetic
/knowledge/software/control-and-path
```

如果未来引入静态站点生成器，可使用 Markdown frontmatter 驱动侧边栏、标签和搜索索引。

## 搜索与筛选

第一阶段可直接依赖站点全文搜索。第二阶段建议生成结构化索引：

- 按年份筛选。
- 按组别筛选。
- 按资源类型筛选。
- 按关键词筛选。
- 按维护状态筛选。

资源信息可以先写在 Markdown 中，成熟后再迁移到 `data/resources.yml` 或 JSON 文件。

## 可持续维护策略

- 每个页面保留“待补充”区域，降低第一次贡献门槛。
- 对不确定信息显式标注“待确认”。
- 每季度巡检一次高频入口链接。
- 优先维护入口页质量，再扩展深层页面数量。
- 允许同一资源出现在多个入口，但避免复制长篇说明。
