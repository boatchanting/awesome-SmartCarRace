# 调试与测试流程

智能车竞赛的调试核心是让问题可复现、可定位、可回退。没有记录的调参很容易变成猜测。

## 推荐调试闭环

```text
提出假设 -> 设计测试 -> 记录数据 -> 分析结果 -> 修改参数或代码 -> 回归验证
```

## 日志内容

建议至少记录：

- 时间戳或周期计数。
- 传感器关键值。
- 路径偏差、曲率、识别状态。
- 速度目标、方向目标、控制输出。
- 当前状态机状态。
- 关键参数版本。

## 参数管理

参数建议集中管理，避免散落在代码各处。

可以按类别组织：

- 传感器标定参数。
- 图像或信号处理阈值。
- PID 参数。
- 速度规划参数。
- 特殊元素策略参数。

## 测试场景

每次重要修改后，至少验证：

- 直道稳定性。
- 连续弯道。
- 起步和停车。
- 低电压或电池变化。
- 特殊元素进入和退出。
- 传感器短暂异常。

## 复盘记录

建议每次训练后记录：

- 日期、场地和车辆版本。
- 修改内容。
- 成功现象。
- 失败现象。
- 可能原因。
- 下一步计划。

长期看，复盘记录比单次参数更有价值。
